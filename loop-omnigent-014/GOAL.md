DIAGNOSIS (from a live trial on 2026-09-17, evidence in /tmp/omnigent-dev-data/evidence/ if still present, plus /home/coder/omnigent-dev/loop-v14-rebase/)
1. Runner discovery. `broker_http.create_session` (~289-370) POSTs `/v1/sessions` without `host_id`, then requires exactly one online runner from `GET /v1/runners` and PATCHes the session onto it. A fresh host has zero runners (both 0.12 and 0.14 spawn runners per session; on the live box this is masked by UI sessions' runners), so the headless loop aborts with `cannot start session: expected exactly one online runner, found 0` AND leaves the already-created session orphaned (not in `.driver.json`, not pruned). The server-sanctioned flow on both versions: `POST /v1/sessions` accepts `host_id` (+ workspace) so the server launches a dedicated runner on that host (see /home/coder/omnigent-dev/omnigent/server/routes/_sessions/orchestration.py ~8120-8140 and ~8790-8830, `body.host_id`), and `POST /v1/hosts/{host_id}/runners` with `{session_id, workspace}` launches one for an existing session (routes/hosts.py ~463-480 and ~733-760; the same route exists in 0.12 at hosts.py:729). Sharing one runner between the Lead, Evaluator and other sessions also caused the transcript-mirroring collision below and is what orphaned role sessions when a shared runner's 1h idle timeout fired in earlier loops.
2. First-prompt race. With a cold cursor-native session the runner forwarded the first message (`_run_turn_bg ... POST harness.local/v1/sessions/<id>/events 200`) but the Cursor TUI was still on its welcome screen; the prompt stayed in the session's pending inputs and no item was ever stored. 2 of 2 loop attempts hit it, a later single trial did not. trioctl's `_is_restart_blip` retry (~1741-1800) then created a DUPLICATE Lead session 12 s later and gave up; the loop exited 3 with `phase: error`. Same race exists on 0.12 (seen with sys_session_create on the live box the same day).
3. Transcript mirroring collision: several cursor-native sessions on one runner in the same workspace made the forwarder log `cursor chat ... store.db already mirrored by another session; pausing`, so `items` never grew and `_wait_for_session` saw zero items forever.
4. `trioctl omnigent doctor` (~385-405) probes `from omnigent.server.routes.sessions import _resolve_agent_spec`; upstream 0.14 only has `_resolve_subagent_spec` (the 0.14 fork branch adds an alias). SKILL.md's offline validation `-k` selector names `registered_native_agent_create_derives_launch_args_from_root_spec`, a test that exists only in the old fork.
