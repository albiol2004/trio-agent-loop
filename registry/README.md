# Registry

The registry system provides format-aware scanning, canonical-agent definitions, and per-harness installation rendering. All code is stdlib-only (Python 3.11+).

## Overview

One canonical entity is stored per harness and eliminated the need for hand-syncing formats: a canonical agent is defined once in `registry/canonical-agents/` and rendered into each supported harness's native agent format. Server-side serialization lives in `dashboard/serve.py` only, so no second format writer can diverge.

Installations are compared against canonical renders for drift detection: in-sync, stale, missing, or unsupported.

## `scan.py` — format layer and registry index

`registry/scan.py` is a **read-only scanner** that parses every harness's skill/command/agent registry, hashes content for drift detection, and emits `registry.json`. It also owns the **format layer** used by the dashboard editor:

- **YAML-subset parser/serializer** — hand-written (no PyYAML; stdlib only), lenient for on-disk scanning (a bad file must not kill a scan), strict when parsing user-submitted YAML. Round-trips: `parse(dump(parse(text))) == parse(text)` with key insertion order preserved.
- **TOML parser/serializer** — `tomllib`-backed for parsing, minimal custom serializer for output. Round-trips order-preserving.
- **Frontmatter parsing** — YAML frontmatter (delimited by `---`) is split from body; body digests are computed separately from frontmatter for drift detection (frontmatter legitimately differs per harness; body drift signals staleness).

Canonical paths (e.g., files generated by `prompts/generate.py`) are marked `managed=true` in the index so the dashboard renders them read-only. Loading is best-effort and memoized — any failure yields an empty set rather than breaking a scan.

Usage:
```bash
python3 registry/scan.py [--out registry/registry.json] [--project DIR]
```

Key functions:
- `collect()` — scan one project's harness directories
- `collect_canonical()` — scan `registry/canonical-agents/`
- `build_index()` — group entries by surface/harness and compute drift status
- `parse_frontmatter()`, `join_file()` — frontmatter/body manipulation
- `parse_yaml()`, `parse_toml()` — format-specific parsing

## `agents.py` — canonical-agent model and renderers

`registry/agents.py` defines the **harness-neutral canonical agent**:

```python
@dataclass
class CanonicalAgent:
    name: str                    # lowercase alphanumeric + ._-
    description: str             # required, non-empty
    instructions: str            # markdown body
    model_tier: str              # "standard" | "high" | "cheap"
    tool_policy: str             # "read-only" | "edit" | "spawn"
```

Canonical agents are stored as `registry/canonical-agents/<name>.md` (YAML frontmatter + Markdown body).

### Model tiers

Map to each harness's native model selection:
- **high** — Opus, GPT-5.6-terra, Cursor Grok 4.6-high
- **standard** — Sonnet, GPT-5.6-luna, Cursor Grok 4.6-medium
- **cheap** — Haiku, GPT-5.6-luna (low effort), DeepSeek v4-flash

### Tool policies

Control sandbox/permission levels:
- **read-only** — disallow Write/Edit/Agent (claude), sandbox_mode read-only (codex), read-only tools (omp/opencode)
- **edit** — allow file writes, disallow Agent spawn (except opencode which allows with permission)
- **spawn** — full agent-spawn permissions

### Per-harness renderers

A canonical agent is rendered into each harness's native file format via `render_agent()`:
- **claude** — `<name>.md` (YAML frontmatter + body)
- **codex** — `<name>.toml` (TOML frontmatter, `developer_instructions` body)
- **omp** — `<name>.md` (YAML frontmatter + body)
- **opencode** — `<name>.md` (YAML frontmatter + body, `mode: subagent` + `hidden: true`)
- **omnigent** — not supported (omnigent agents are Terraform role directories with config.yaml, managed by `prompts/generate.py`)

The index builds `agent_matrix` by comparing each canonical render's `body_hash` against installed agent body hashes to detect staleness.

## Test suite

Run all 164 tests:
```bash
python3 -m unittest discover -s registry/tests -t .
```

Tests cover:
- **scan.py** — YAML/TOML parsing, frontmatter splitting, format round-tripping, lenient vs strict modes
- **agents.py** — canonical-agent parsing, validation, rendering, per-harness serialization
- **serve.py** — registry file serving, schema endpoints, serialization validation, agent CRUD, install API
- **page rendering** — agents.html matrix generation, skills.html schema forms

Key test files:
- `test_scan.py` — parser/serializer correctness and edge cases
- `test_agents.py` — canonical-agent models and renderers
- `test_serve_registry.py` — registry file API
- `test_serve_agents.py` — canonical-agent CRUD and install endpoint
- `test_serve_pages.py` — dashboard page generation
