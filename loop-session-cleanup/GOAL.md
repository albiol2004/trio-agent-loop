## Problem (diagnosed 2026-09-16, evidence in the coordinator session)
Trio Omnigent loops create Lead/Evaluator sessions (provider cursor, model cursor-grok-4.6-medium; the same applies to claude-native and codex-native registered roles) that run an interactive vendor TUI inside a dedicated tmux (`/tmp/omnigent-terminal-*/tmux.sock`, 200-600 MB resident each). Ten idle role sessions from finished loops accumulated ~5 GB inside a 12 GB workspace cgroup and OOM-killed the rootless Docker daemon.

Root causes on the trio side:
1. Skill driver (`omnigent/entrypoints/trio-omnigent/SKILL.md`): cleanup (step 8, lines ~160-167) relies solely on `sys_session_close`. In Omnigent 0.12.x (and upstream through v0.14.0; upstream issue omnigent-ai/omnigent#7498) that call is refused with `session_not_a_sub_agent` for `sys_session_create` children because a title-parse guard in `omnigent/runner/tool_dispatch.py` (`_session_close_via_rest`) requires an internal `<agent>:<title>` form; role titles are plain text (SKILL.md ~113). Even a successful close is a tombstone + interrupt that does not free the terminal. The only external path that kills the tmux is a broker session DELETE (`DELETE /v1/sessions/{id}`), which `trioctl omnigent sessions prune --include-sub-agents` already performs but only for titles starting with `trioctl <mailbox.name> ` (trioctl ~1062-1236). Skill role titles do not carry that prefix, so prune cannot find them. Cleanup is also only specified for four terminal states, not for coordinator abort/interruption.
2. Headless driver (`trioctl omnigent loop`, trioctl ~1713-1762 `command_loop`, `_run_post_loop_session_prune` ~1209-1236, `_prune_broker_sessions` ~1062-1171): cleanup runs only on normal Python exit (no SIGTERM/SIGINT handling), and a session whose transcript archive fails is kept, not deleted (~1149-1160), silently retaining its terminal.

An Omnigent-side loop (separate mailbox in the fork worktree /home/coder/omnigent-dev) is fixing the close tool itself in parallel; this mission must make the trio drivers correct and leak-free even against an unfixed Omnigent.
